# 每日科技动态

今天这组更新有一条很清晰的主线：各家平台都在把“边界”做得更显式。浏览器在权限和平台能力上减少隐式行为，GitHub 在 agent 自动化里补上协议与审核边界，AI 产品则开始把个人数据接入和企业级 agent 运行方式做成标准化能力。由于最近 24 小时前端官方一线更新偏少，本文前端部分适度放宽到最近 7 天，优先保留对开发工作流影响最直接的官方条目。

# 今日概览

# 前端

Safari Technology Preview 248 继续把新 Web 能力往“可试、可测、可逐步依赖”推进。 7 月 22 日，WebKit 发布《Release Notes for Safari Technology Preview 248》。官方 release notes 显示，这一版新增了 CSS progress() 函数的 no-clamp 选项、补上了类似颜色空间插值时对缺失颜色分量的转发支持，同时在 JavaScript 侧新增了 TC39 BigInt Math 提案支持，暴露出 BigInt.pow、BigInt.sqrt 等与 Math 对应的方法。对前端团队来说，这类 STP 更新的意义不只是“又多几个实验特性”，而是能更早判断 Safari 端哪些 CSS/JS 能力正在进入真正可落地的实现阶段。来源open in new window

Firefox 153 让扩展开发里的文件访问权限和文档定位语义都变得更明确。 7 月 23 日，Mozilla 发布《Firefox 153 WebExtensions API updates》。官方正文显示，从 Firefox 153 开始，扩展访问 file:// URL 不再默认包含在“访问所有网站数据”的 host permission 里，而改成单独、显式的“Access local files on your computer”权限；同时 extension.isAllowedFileSchemeAccess() 会准确反映用户是否已授权。除此之外，Firefox 153 还加入了 userScripts.execute()、publicSuffix API、runtime.getDocumentId() 及更多基于 documentId 的能力，并允许内容脚本直接读写 document.adoptedStyleSheets 与 ShadowRoot.adoptedStyleSheets。这意味着扩展开发者需要更认真地处理权限提示、文档实例定位和样式注入边界，而不是继续依赖过去的隐式行为。来源open in new window

# DevOps

GitHub MCP Server 提前切到下一版 MCP 规范，agent 基础设施开始从“有状态握手”转向“更易扩展的无状态核心”。 7 月 23 日，GitHub 发布《GitHub MCP Server supports the next MCP specification》。官方正文显示，MCP 协议将在 7 月 28 日转向 stateless core，GitHub MCP Server 已提前支持新规范。变更重点包括：新的无状态核心更易扩缩容；会话与 initialize 被移除，客户端可以更快建立连接并并行完成握手；GitHub 侧还去掉了 initialize 时的数据库写入和各请求中的数据库读取，并改为从保证存在的 HTTP headers 读取部分日志与 secret scanning 所需字段。对做 agent 平台、MCP 网关和内部工具集成的团队来说，这条更新的价值在于：协议底座开始朝“更像标准 Web 服务”收敛，部署和兼容策略会因此变得更工程化。来源open in new window

GitHub Issues 开始为 agent 自动化补上“建议、置信度、理由”三层审核机制。 7 月 23 日，GitHub 发布《Agent automation controls in GitHub Issues in public preview》。官方正文显示，新的能力允许自动化先“suggest”而不是直接应用变更，待处理建议会挂在 issue 面板里由用户逐条接受或拒绝；agent 还会对支持的动作给出 high / medium / low 置信度，高置信度可自动应用，中低置信度则转为待审核建议；每一次加标签、改字段、改 type、关闭 issue 或分配 assignee 的操作都会记录 rationale。GitHub 还提供 has:suggestions 搜索条件，并允许仓库管理员设置 automation level 与置信度阈值。对 DevOps 和工程治理团队来说，这代表 agent 自动化正从“能不能做”进入“怎么可审计地做”的阶段。来源open in new window

# AI

OpenAI 把健康数据接入 ChatGPT，开始把“个性化 AI 助手”往受监管、高敏感数据场景推进。 7 月 23 日，OpenAI 发布《Launching Health in ChatGPT》。官方 RSS 显示，Health in ChatGPT 允许符合条件的美国用户安全连接医疗记录和 Apple Health，以获得更个性化的健康洞察和更好的健康理解。官方搜索摘要进一步显示，这一体验还强调额外的隐私、安全与隔离保护，并可接入 Apple Health、Function、MyFitnessPal 等健康数据源。相比普通知识问答，这条更新更值得关注的点在于：OpenAI 正在把 ChatGPT 从“会回答问题”推进到“能够围绕高敏感个人上下文提供持续辅助”的产品形态。来源open in new window

Anthropic 把 Economic Index 做成 Claude 连接器，直接把“AI 与工作的真实数据”嵌进对话界面。 7 月 22 日，Anthropic 发布《Ask Claude about the Anthropic Economic Index》。官方正文显示，这个连接器允许用户在 claude.ai 的 connectors 目录中直接启用 Anthropic Economic Index，无需安装，可在任意对话、任意 Claude 模型中使用；用户既可以先问“我的行业发生了什么变化”，也可以继续追问并要求 Claude 展示底层数据。它的意义不在于又多了一个连接器，而在于 Anthropic 正把“关于 AI 如何影响工作”的研究数据产品化，让模型不只生成观点，还能在对话里直接连接到可追溯的数据依据。来源open in new window

# 今日观察

今天最值得关注的不是单点功能，而是各类系统都在减少“默认帮你猜”的空间。Firefox 把本地文件访问从隐式权限拆出来，GitHub 为 agent 变更补上建议、置信度和理由，MCP 规范则把协议推进到更易扩展的无状态实现；OpenAI 和 Anthropic 则分别把健康数据与劳动研究数据接进模型界面。对开发团队来说，这意味着下一阶段的竞争点不只是功能堆叠，而是谁能把权限边界、审核边界和数据边界做得足够清楚，同时又不牺牲交付效率。
